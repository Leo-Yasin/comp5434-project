# Task2跨机冷启动复现差异：初步排查

用户截图：朋友已生成10000行且ID顺序相同，但相对参考CSV平均绝对差0.017659、最大绝对差0.524114。
这些差异不属于先前单/四线程导致的约2.958e-7舍入差，不能称为完整复现成功；无真实标签也不能计算新官方RMSE。

## 已确认的交付验证边界

此前逐字节一致的验证在本机执行，并复用了输入/参数绑定的冻结特征缓存。
它验证原始CSV特征重建、组合头和最终评分一致，没有证明另一台电脑从零运行全部编码器也会生成相同特征。
旧BERT的embedding_infer缓存指纹包含输入/模型/分词器/批量，但缺少ORT版本、CPU指令路径和源码版本信息，是实际存在的复现保护缺口。
模型包是Round10，并含必要父模型；若朋友使用未修改的round10_predict，入口会逐文件检查模型SHA。仍需取得实际命令以确认她运行了该入口。

## 尚未确认的可能来源

- 入口/模型层级选择、测试内容或文本处理不同；10000行及ID相同不能证明正文相同。
- 三套Python环境未按原版本隔离，或者旧缓存混用了不同运行环境的编码结果。
- 动态量化旧BERT在不同CPU、ORT版本或批组成下产生差异。
- 英语/适配/标题等中间结果或组合特征不同，需逐层比较后才能定位。

ORT官方说明量化U8S8在部分CPU指令路径可能发生饱和误差；这是排查依据，不是朋友案例的已证实原因：
https://onnxruntime.ai/docs/performance/model-optimizations/quantization.html

本地Round9与Round10参考CSV的平均/最大绝对差为0.0272084553/0.7462027512，与截图不相等，故不能直接断言朋友只是跑了Round9。
