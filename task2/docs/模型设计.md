# Task 2 模型、并行计算与验证设计

## 问题与约束

输入是评论标题/正文、用户、商品、父商品、时间、帮助票数和购买状态。
预测评分 1–5，以 RMSE 衡量连续预测误差。训练集超过 768 万条，文本文件约 2 GB。
课程要求实际使用大数据并行或分布式框架，并报告完整效果、硬件与效率数据。

## 验证设计与评分统计隔离

id 是各文件内部行号，不作为输入，也不用于跨文件重复判断。
由 title、comment、user_id、prod_id、parent_prod_id、time 组成评论组；
按稳定 64 位哈希 mod 100 < 2 留出开发验证，重复评论组不跨界。
64 位哈希理论上可能碰撞，审计计数应理解为基于哈希的近似身份统计。

数据不是未来预测任务的明确时间切分，因此本地验证采用评论分组的随机式留出，
并另外报告 warm（用户、商品都在训练部分出现）与 cold 子组。
测试标识符都在全训练集中出现，不代表所有验证样本也都属于 warm。

对用户、商品、父商品分别计算：

```text
smoothed_mean = (sum_rating + strength * prior) / (count + strength)
features = [smoothed_mean - 3, log(1 + count)/10, count == 0]
```

平滑强度依次为 5、20、20。验证行只使用外层训练标签。
模型训练行再按评论组 mod 5 交叉拟合，评分和先验都排除自身所在整折。
因此改变某条训练记录的标签不能改变它自己的输入统计；改变验证标签也不能改变任何输入。
相关不变量由单元测试检查。

实现上通过 uint64 键排序、searchsorted 和 bincount 完成统计及推理查找，
不用数百万 Python 对象组成的字典。按字段和模式顺序处理，并将大数值特征写入磁盘映射。
完整模型的训练行也交叉拟合；测试行才使用所有训练评分的统计。

## 文本与基础数值特征

标题与正文分别使用 signed feature hashing：标题 32,768 维、正文 262,144 维，
保留一元词与二元词组，包括否定词。各自 L2 归一化，标题权重为 1.5。
不学习全局词表或 IDF，不需要用验证语料估计参数。

固定变换的基础数值字段包括截距、帮助票数 log1p、购买状态、标题/正文长度 log1p、
时间尺度、感叹号数量及空正文标记，共八维。所有缩放常数在实验前明确设定。
所以本文的 text 消融更准确地指“文本 + 不含评分的基础字段”。

HashingVectorizer 是第三方通用特征工具，不是预测器。它以固定内存代价编码稀疏词组，
可能发生特征碰撞，这是效率与精度之间的明确取舍。

## 自主评分模型与预条件共轭梯度

模型为连续回归：prediction = mean + Xw，最终截断到 [1,5]，不取整。
训练目标是 sum((Xw + mean - y)^2) + w.T R w。
通常特征的 R 对角值为 20，截距为 1e-6；mean 由当前允许使用的训练评分计算。
正规方程为：

```text
A = X.T X + R
b = X.T (y - mean)
A w = b
```

不显式构造 A，避免约 29 万维的稠密二次方矩阵。
主进程保存参数向量，通过各工作进程返回的 X_k.T(X_k p) 计算 Ap。
Jacobi 预条件器为 M = diag(X.T X) + diag(R)。初始 w=0，r=b，z=r/M，p=z。
每轮自行实现：

```text
alpha = (r.T z) / (p.T A p)
w_new = w + alpha * p
r_new = r - alpha * A p
z_new = r_new / M
beta  = (r_new.T z_new) / (r.T z)
p_new = z_new + beta * p
```

一次迭代完整访问所有训练分区，另有初始化统计遍历。记录每轮时间与正规方程相对残差。
当残差低于 1e-6 时停止，或者达到设定的迭代上限。
开发阶段在若干迭代检查验证 RMSE 并保存最好参数；全量训练复用选定轮数，不报告伪验证分数。
有限轮数的解不能宣称已经完全收敛，实际残差在 history.json 中保留。

## Dask 实际职责与内存控制

- 流式 CSV 解析：正确处理评论内换行，不按任意字节边界拆分 CSV。
- 多进程特征编码：每 50,000 条一块，主进程最多保留有限在途块。
- 训练并行：工作进程读取各自分区，执行右端项、对角与矩阵向量积。
- 参数方向通过 scatter 广播一次，避免每个分区重复序列化同一向量。
- 归约按分区固定顺序执行，不由完成顺序决定浮点累加次序。
- 工作进程只缓存两个分块，主进程不收集全量文本或大矩阵。
- 多次训练遍历使用内存映射 CSR，避免反复 ZIP 解压；转换前后逐数组核对一致。

这是一台机器、三个工作进程的并行执行，不能描述成三个服务器。
Dask 官方框架说明：https://docs.dask.org/en/latest/user-interfaces.html 。

## 自主技术贡献与评估限制

自主实现包括交叉拟合评分统计、泄漏隔离、分区计算、固定顺序归约、Jacobi-PCG、
预测导出与可复现检查；不调用现成 Ridge、分类器或回归器训练函数。

模型与迭代次数依据当前验证集选择，因此验证结果用于开发，不是独立测试成绩。
训练单次耗时可能受后台任务影响。另用相同数据与向量比较 1/3 进程核心算子，
明确范围与计时边界，不将小规模算子加速比当作全量端到端训练速度。
