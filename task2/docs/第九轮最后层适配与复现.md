# 第九轮：最后层适配的理解与复现

本轮最新实际结果以根目录 `docs/Task2第九轮优化结果-20261114.md` 为准。此前第八轮 Kaggle RMSE=0.50646。
本文件解释实现与复现边界，不代表任何尚未测评版本已获得线上提升。

## 哪些参数改变了

仍从固定的 `patrickvonplaten/deberta_amazon_reviews_v1` 权重版本
`06f020e0dbf909570eb886423bd3af256b855546` 开始，原许可证 MIT，原模型卡语料信息不完整，重叠未知。
前11个Transformer编码层及其词嵌入、相对位置表固定，只更新第12层、原pooler和五星分类器。
这属于部分编码层微调；不能称为整网微调，也不同于仅拿固定CLS做线性回归。

最后层仍执行内容/相对位置解耦注意力、前馈网络、残差和LayerNorm。
它的query/key/value和前馈权重会接收课程评分损失的梯度，使编码表示适应本课程。
原相对位置嵌入经过原LayerNorm后的常量作为buffer保存，不被优化器更新。
编码层变化、冻结消融以及数学梯度均有独立核验，不能只凭`loss.backward()`判断所有目标层都被训练。

GPU无梯度预测批量可由16提高为64，但只在`gpu_prediction_batch_audit.json`明确通过时用于128token缓存。
核对使用64个内部拟合输入，包括上限长度和短输入，比较真实适配快照的logits/CLS；不读取检查或确认评分。
未通过则保留16。训练微批16、累积64、256token推理批16以及最终CPU部署批16不受影响。

## 为什么2GB显存能做

先对无标签正文计算冻结前11层输出，按有效token紧凑保存；GPU训练时只加载最后层及分类头。
开发输入83047行、2944295个有效token，128上限的float16缓存约4.52GB，存在C盘。
缓存近似只作用于隐向量存储，前缀网络和可训练权重保持FP32；用真实输入比较完整logits和CLS误差后才使用。
padding不作为key；最后层没有卷积，恢复补零padding不影响有效token的注意力，已实际核对。
缓存只依赖正文、固定模型和分词器；课程评分不进入缓存生成过程。

## 噪声损失与输出

潜在干净分布为`q=softmax(logits)`，观测分布为`r=(1-epsilon)*q+epsilon/5`。
自定义损失`-log(r[y])`用`logaddexp`稳定实现，epsilon沿用固定估计0.25165131324376977。
当某个观测与模型不一致时，其梯度乘以来自干净通道的责任权重，缓和随机替换标签的影响。
输出使用`sum((k+1)*q[k])`的连续评分期望；不取整数argmax，不对期望重复逆噪声校正。

另比较固定旧模型去噪后验目标。以相应阶段第八轮的五星概率`t[k]`作先验，构造
`target[k] = t[k]*((1-epsilon)*1[k=y]+epsilon/5) / ((1-epsilon)*t[y]+epsilon/5)`，
再用软交叉熵训练新网络。目标只在允许拟合行按其观测评分构造。
当学生对正确困难标签的概率接近零时，原噪声似然梯度也可能接近零；固定后验目标可以提供直接梯度。
这是数学上的机制差异，不能替代验证效果。旧模型先验也可能错误，并非干净标签真值。
教师是项目第八轮融合器，不是外部API；其训练行预测没有在当前拟合子集内完全交叉拟合，存在先验偏差风险。
确认阶段只使用第八轮confirm模型，不能偷换成已见确认标签的final模型。

还比较保留第八轮类别偏置的残差目标：`effective_logits = old8_logits + new_english_logits - frozen_english_logits`。
初始模型未改变时，修正量在浮点误差范围内为零，保留已有历史/文本融合能力；用相同噪声通道损失训练修正。
相应阶段的旧偏置固定，梯度只进入新英语最后层/分类头。推理也必须做相同组合，原始英语输出不能直接当成最终评分。

使用FP32 AdamW，编码层学习率1e-5或3e-5，原pooler/classifier为其5倍；微批16，累积有效批64。
前5%更新warmup，其后按总计划两轮衰减。即使内部选择第一轮快照，重训仍采用两轮计划的前半段调度。
种子5434，实际训练启用确定性算法；保存的是张量state_dict，加载使用`weights_only=True`。

## 如何选择与确认

内部训练33437行、检查8268行，只在这些行选择；确认41342行，最后才用全部83047行拟合最终模型。
输入最长128/256作为推理对照：256仅为达到原128上限的4078行增加前缀缓存，最后层训练仍用128上限。
先对256动态相对位置、FP32拆分、缓存精度和显存单独核验，未通过的实现不能进入效果比较。
上下文扩展是在内部基线长度诊断之后、首个新神经效果产生之前登记，不把它描述成早于全部内部分析。

原噪声目标两学习率、固定后验目标1e-5、残差噪声目标3e-5共四种训练组合；每组两快照、两输入长度。
每个快照/长度比较四个凸组合、两个低维噪声头，以及两个加入更新CLS的强正则头（L2=1000/5000），共128个候选。
后验目标是在第一组课程训练已开始、查看任何新内部验证指标前登记。
CLS及残差扩展发生在首个固定半融合只读诊断未胜出之后；原24/48/72/96计划保留，不声称全部方案首次就已确定。
若实现审计排除某长度，实际范围以selection_protocol.json为准。
融合为0.25/0.5/0.75/1评分凸组合，或L2=100/1000的低维自主噪声校准头。
低维校准输入35列旧结构、旧评分和新分布；另比较加入768维更新CLS的强正则头。
适配CLS在当前拟合行上并非OOF，存在训练内/外表示差异，强正则不能替代独立组检查和冻结确认。
配置在确认前冻结；不做适配、只训练pooler/classifier的确认消融仅用于归因，不据其重新选型。
分组存在历史复用，本地风险依赖均匀随机评分替换假设，不等于Kaggle分数。

## 队友如何预测

Git不含大型Task2参数。向维护者取得完整第九轮model文件夹，放到`task2/latest/model`。
该目录包含previous_model完整第八轮基础参数、adapter冻结前缀和已适配最后层、必要校准头及逐文件SHA清单。
本机因F盘空间有限，把新完整包存放在`C:/Users/Leo/.cache/comp5434-local9/model`，实际位置见本轮model_reference.json。
包内prefix可能采用同卷硬链接节省本机空间；它是普通文件目录项，复制整个包即可，不依赖旧缓存路径继续存在。

1. 数值环境按`task2/requirements.txt`安装（原Python3.9）。
2. 旧BERT环境按`requirements-semantic.txt`安装（Python3.12）。
3. 英语CPU环境按`requirements-english.txt`安装，并安装官方CPU版PyTorch2.6.0：

```powershell
python -m pip install torch==2.6.0 --index-url https://download.pytorch.org/whl/cpu
```

在仓库根目录执行，环境路径按自己的电脑替换：

```powershell
& ".venv-numeric/Scripts/python.exe" -m task2.round9_predict --model task2/latest/model --test comp-5434-20261-project-task-2/test.csv --semantic-python .venv-semantic/Scripts/python.exe --english-python .venv-english/Scripts/python.exe --work-dir task2_inference_round9 --output task2_prediction_round9.csv
```

预测使用CPU，无需CUDA；数值、旧BERT和英语环境保持隔离。训练环境才使用torch2.6.0+cu124。
原始CSV重建历史、词和数值特征；冻结编码只有在输入、网络、分词器和配置指纹一致时复用。
所有最终评分都会重新计算，训练缓存、旧提交CSV和训练标签不作为预测输入。
计时明确记录冻结编码的复用行数；不能把缓存核验时间当成全新端到端编码时间。

## 从训练产物复现

需要原始数据、固定ID划分和前轮基础模型/缓存；只克隆最新版代码不能直接执行所有历史训练脚本。
`partial9.prepare`拆出前缀和初始最后层；`partial9_audit`核验实现，`partial9_cache`生成无标签缓存。
`partial9_train`分别拟合inner/confirm/final，`partial9_fusion`完成内部选择、冻结确认和最终校准。
`tools.finish_task2_round9`准备模型包并校验原始CSV独立预测；不调用Kaggle提交接口。
前11层没有用课程数据微调，最后层也仅用对应阶段的开发子集；不能声称在全部768万条课程数据上做了神经微调。
