# DeBERTa与本地量化：理解和答辩说明

## 本项目准备研究什么

已有的多语言BERT和五星词模型已得到线上0.53719。本轮检查英语评论编码器能否提供不同的语义表示。
模型是patrickvonplaten/deberta_amazon_reviews_v1，固定版本06f020e0dbf909570eb886423bd3af256b855546，MIT。
作者教程用英语Amazon Reviews Multi进行五星分类并发布同名仓库，但单独模型卡的训练数据部分不完整，
因此保留来源和语料重叠未知的限制，不把教程数据规模当成精确可审计的本权重训练清单。
本项目不下载原始外部评分答案；老师允许的外部预训练模型条件仍是需要理解模型。

## 编码器为什么可能不同

配置为12层、隐藏维768、12个注意力头，每头64维；SentencePiece词表128100。
多语言BERT主要使用绝对位置编码，DeBERTa把内容和相对位置的作用分开。
注意力可理解为“内容看内容”加上“内容看相对位置”和“位置看内容”。
这样同一个词在不同相对位置上的含义可以分开表达，例如否定词与被否定短语的关系。
DeBERTaV3的预训练还使用替换词检测；它和本课程的随机评分噪声是两个不同机制，不能混为一谈。
前者作用于预训练输入token，后者作用于本课程训练标签。

本项目用正文输入，按作者教程128 token截断；标题仍由旧模型处理。
取两类结果：预训练五星logits，以及最后一层首token的768维CLS。
CLS不同于经过Dense/GELU后的pooler，也不同于五个最终类别分数。
新本地头学习如何把这些信息与旧预测组合，而不是直接把外部模型的星级当成真值。

原模型的SentencePiece使用byte fallback；Fast转换对这部分可能不完全等价，
因此实际推理保留原SentencePiece分词器，不以速度为由默默换掉罕见字符处理。

## CPU部署为什么需要额外校验

原PyTorch到FP32 ONNX导出在多个batch/长度上和原模型logits的最大误差约1e-6，符合浮点舍入范围。
但默认INT8方案在简单样例上就出现约6的logit误差，不能说“导出成功就是模型一样”。
缩减范围、逐通道量化在两个样例上改善，但128条实际内部训练输入的类别一致率仅81.25%，仍被拒用。
类别一致率只比较两种实现，不是用训练评分测出来的分类准确率。

## 自主SmoothQuant式变换

参考Xiao等人的SmoothQuant思想，自行实现以下等价变换：

`xW = (xD^(-1))(DW)`，其中D是正对角矩阵。

对每个Linear输入通道，记录内部训练正文上的最大绝对激活a，并从权重计算每输入通道最大绝对值w。
用`D[j]=sqrt(a[j]/w[j])`，对极端值作固定截断，既降低激活离群值，又避免只让权重承担全部动态范围。
ONNX中在MatMul前插入逐通道除法，并把对应权重行乘回相同尺度。
FP32函数在数学上不变，只有运算舍入可能变化；之后再量化是近似过程，仍需实际输入审计。
本实现保留Gemm的FP32，避免量化相对位置投影、pooler和分类头。

这不是对DeBERTa的梯度微调，但存储张量经历了等价重参数化和量化。
因此严谨表述是“没有微调编码器”，而不是声称每个保存的权重比特完全没有改变。
校准只用内部训练正文，不使用课程评分、确认组标签或测试答案。
真实输入的logit误差、CLS相对误差和类别一致率都需通过门槛，未通过就不能进入课程效果验证。

本轮实际实现检查中，SmoothQuant式FP32分支修复共享权重后保持等价，但INT8仍没有通过真实输入门槛。
因此这些INT8版本没有纳入课程效果验证。当前采用原FP32 ONNX网络和OpenVINO CPU FP32实现，
在128条输入上与已核对的ORT FP32输出全部同类，logit平均误差约1.4e-6。
这只是数值实现的一致性，不是新的课程分类准确率或Kaggle成绩。

## 和课程模型如何连接

潜在五星分布q对应干净标签，观测分布`r=(1-epsilon)q+epsilon/5`，用`-log r[y]`训练本地组合器。
模型类别索引0–4对应评分1–5。提交连续评分为`sum((k+1)*q[k])`，即干净评分的条件期望，
不能先取argmax或四舍五入，也不能把含随机噪声的r期望直接当成干净评分。
epsilon来自训练部分的原噪声估计，不能根据Kaggle分数反复调。
内部选择用固定8268条，确认用41342条；这些验证行存在历史复用，不能声称全新独立测试。
词模型在Dask上进行实际大规模并行训练；英语网络是CPU批量推理，不宣称是Dask训练了DeBERTa。
