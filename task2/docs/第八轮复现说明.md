## 队友直接预测

GitHub 只提供代码、阶段记录、配置和最新提交 CSV，不提供大型 Task2 模型包。
向维护者取得 `task2/outputs/round8_20261114/model` 整个文件夹，放到克隆仓库的 `task2/latest/model`。
该包包含前轮基础词模型、历史查找表、预测头和冻结语义网络，无需训练缓存、历史提交 CSV 或训练标签。

使用三套独立环境，避免原 Python 3.9 的 Dask/NumPy 和新运行时互相覆盖：

1. 数值环境：按 `task2/requirements.txt` 安装，原实测 Python 3.9、NumPy 1.21.5、SciPy 1.9.1。
2. 旧 BERT 推理环境：按 `task2/requirements-semantic.txt` 安装，保留原运行时版本。
3. 英语推理环境：Python 3.12，按 `task2/requirements-english.txt` 安装。

在仓库根目录执行，三个 Python 路径替换为自己的虚拟环境路径：

```powershell
& ".venv-numeric/Scripts/python.exe" -m task2.round8_predict --model task2/latest/model --test comp-5434-20261-project-task-2/test.csv --semantic-python .venv-semantic/Scripts/python.exe --english-python .venv-english/Scripts/python.exe --work-dir task2_inference_round8 --output task2_prediction_round8.csv
& ".venv-numeric/Scripts/python.exe" -m unittest discover -s task2/tests -v
```

`model.json` 决定是否使用英语网络。使用时必须是经过精度核对的原 FP32 ONNX，OpenVINO 2025.3.0 CPU、4 线程、batch16、最长128 token。
拒绝用已失败的 INT8 图替换；输入/网络/分词器/配置的哈希变化会拒绝继续旧断点。
已有编码断点可以加速相同输入的核验，计时文件会记录复用行数，不能把复用时间称为重新编码耗时。

## 从训练产物重做本轮

这不是只克隆仓库即可执行的训练流程，依赖原始数据、原稀疏缓存和前轮分组/模型产物。
不得以新 pandas 默认空值规则重建原验证划分；固定 ID 清单及 `task2.audit.CSV_OPTIONS` 是复现边界。

1. `task2.tfidf_sparse` 只在原外层训练行统计 IDF；`task2.sparse_noise` 用新表示、L2=5 继续40次缩放 L-BFGS，保留20/40次权重。
2. `task2.english_prepare` 固定公开仓库版本和 SHA，使用 `weights_only=True` 加载张量；CPU 导出 FP32。下载可显式传 `--proxy`，代码不写入个人代理地址。
3. `task2.english_backend_audit` 先核对运行时，随后 `task2.english_infer` 对固定83047条开发输入提取 logits/CLS。网络不微调，推理不读标签。
4. `task2.round8_fusion --stage prepare` 建立词输出；`--stage develop --english` 在8268条内部检查数据上选择24个候选并冻结，拟合行33437条。
5. `--stage confirm` 仅一次查看41342条确认数据；消融只做归因，不据确认结果重新选型。通过后才提取测试英语特征并 `--stage final` 拟合最终83047条头。
6. `tools.finish_task2_round8 --stage pack` 打包；以原始测试 CSV 独立调用 `task2.round8_predict`，再 `--stage verify` 核对逐行、字节、格式和旧文件指纹。

词模型没有使用原外层153456条标签，也没有声称在全量768万行重新训练。监督联合头只读取对应阶段允许的标签。
内部和确认数据存在历史复用；条件 bootstrap 不校正选择偏差或噪声假设错误。外部模型训练语料重叠情况未知。
模型结构及量化失败原因见 `DeBERTa与量化原理说明.md`，答辩前应理解而非只记操作命令。
